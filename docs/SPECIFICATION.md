# ChatGPT Usage Dashboard — MVP仕様書

## 1. 目的

ChatGPTワークスペースのAnalytics APIから直近7日間の日次利用集計を手動取得し、管理者が利用状況と異常兆候を確認できるローカルダッシュボードを提供する。

本システムは監査ログや会話本文を取得するものではない。Analytics APIが返す集計情報のみを扱う。

## 2. MVPスコープ

- `.env` のAdmin APIキーをBearer認証に使用する。
- `collect` コマンドを実行した時だけAPIへアクセスする。
- 既定で、実行日の前日までの7日間をUTC日次範囲として取得する。
- ページネーションを追跡し、取得した応答を加工前のraw JSONとして保存する。
- API応答を日付・ユーザー・製品・利用指標のレコードへ正規化する。
- ローカルでは `./data` 配下をストレージとして使用する。
- ダッシュボードは保存済みデータだけを読み、OpenAI APIへ直接アクセスしない。
- Docker Composeで収集コマンドとダッシュボードを実行できる。

## 3. 画面要件

- 収集状態: 最終成功日時、対象期間、データ件数、エラー状態
- KPI: アクティブユーザー、総利用量、日平均利用量、検出アラート数
- 日次利用推移
- ユーザー別利用量ランキング
- 製品別内訳
- 異常兆候一覧
- ユーザー別の日次詳細

## 4. 異常判定

取得指標の種類に依存せず、各レコードの数値フィールドを合計した `activity` を共通利用量として扱う。

- 急増: 当日利用量が直前の利用日平均の2倍以上、かつ10以上
- 大量利用: 7日間全ユーザーの1日利用量の95パーセンタイル以上
- 無活動: 期間内にユーザーレコードはあるが、直近3日間の利用量が0

7日間では統計的な異常検知には短いため、MVPの判定は調査のきっかけとして表示し、断定には使わない。

## 5. データ配置

```text
data/
  raw/<run-id>/page-0001.json
  normalized/usage.jsonl
  state/collection.json
```

- rawは追記専用とし、再調査と正規化処理の修正に利用する。
- normalizedは `(date, user_id, product)` を論理キーとして再収集時に置換する。
- stateには秘密情報を保存しない。

## 6. API接続

- Base URL既定値: `https://api.chatgpt.com`
- Endpoint既定値: `/v1/analytics/usage`
- URLは `OPENAI_ANALYTICS_URL` で上書き可能とする。
- `start_time`（inclusive）、`end_time`（exclusive）、`limit`、`page` を使用する。
- HTTP 401/403はキー、権限、ワークスペースでのAPI有効化を確認する診断メッセージへ変換する。
- 429と5xxは指数バックオフ付きで最大3回再試行する。

具体的なURLと応答スキーマは認証済みAdmin APIリファレンスを正とする。実環境で異なる場合、環境変数とfixtureを更新する。

## 7. セキュリティ

- `.env`、`data/`、APIキーをGit管理しない。
- APIキーをログ、エラー本文、画面へ出さない。
- Dockerイメージに `.env` と収集データを含めない。
- MVPのWeb画面には認証を含めず、ローカルホスト向けとする。本番ではCognito等を必須とする。

## 8. 非機能要件

- 同一期間の再収集で集計レコードが重複しない。
- raw応答はAPIレスポンス変更時にも失われない。
- APIなしでfixtureを使ったテストを実行できる。
- ヘルスチェック `GET /health` を提供する。
- Python 3.12、Docker Compose v2を対象とする。
