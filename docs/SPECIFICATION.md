# ChatGPT Usage Dashboard — 集計CSV版MVP仕様書

## 1. 目的

ChatGPT管理画面から出力した日次集計CSVを管理者が手動アップロードし、ワークスペース全体の利用推移と異常兆候を確認できるダッシュボードを提供する。

個人別データ、監査ログ、会話本文は扱わない。表示する異常は調査のきっかけとなる統計的な兆候であり、不正利用を断定するものではない。

## 2. MVPスコープ

- 「1日のアクティブユーザー数」と「トークン消費量」の2 CSVをブラウザから同時にアップロードする。
- CSV列 `Start Time, End Time, Chat, Codex, Work` を検証し、開始日をキーに結合する。
- UTF-8（BOMありを含む）、非負整数、日付の一意性、両CSVの日付一致を検証する。
- 取込元CSVを加工せず保存し、正規化データは日付単位で冪等に置換する。
- ローカルでは `./data` 配下をストレージとして使用する。
- ダッシュボードは保存済みデータだけを読み、OpenAI APIへアクセスしない。
- Docker Composeでダッシュボードを実行できる。

Chat/Codex/Workのアクティブユーザーには同一人物が重複する可能性があるため、製品間の値は合算しない。全体DAUが必要な箇所では「製品別DAUの最大値」を参考値として明記する。

## 3. 画面要件

- CSVアップロード: アクティブユーザーCSV、トークンCSV、取込結果
- 取込状態: 最終成功日時、対象期間、日数、エラー状態
- KPI: 最新日の製品別最大DAU、期間総トークン、日平均トークン、検出アラート数
- Chat/Codex/Work別の日次アクティブユーザー推移
- Chat/Codex/Work別の日次トークン消費量推移
- 両推移を折れ線グラフで表示し、グラフ上のドラッグで分析期間を指定
- 期間リセット操作で取込済みの全期間へ戻す
- 異常兆候一覧（対象日、指標、製品、実測値、基準値、理由）
- 総トークンの異常分析グラフ（実測値、直前7日中央値、判定ライン、検出点）
- `?` アイコンのホバー／フォーカスで判定条件を表示
- 日次データ表

## 4. 異常判定

各日の直前7日を基準期間とし、5日以上の履歴がある場合に中央値とMAD（中央絶対偏差）によるロバストZスコアを計算する。

分析対象期間を指定した場合、KPI、グラフ、表をその期間に限定し、選択期間全体の中央値とMADで異常判定を再計算する。全期間表示では各日の直前最大7日（最低5日）を基準とする。

- 総トークンおよび製品別トークン: 上振れかつロバストZスコアが3.5以上
- 製品別DAU: ロバストZスコアの絶対値が3.5以上、かつ平均との差が2人以上
- MADが0の場合: トークンは中央値の2倍以上、DAUは中央値の2倍以上または半分以下を代替条件とする

履歴が短い期間や継続的な変化は検出しにくい。アラートは統計的な兆候として表示し、業務事情と合わせて確認する。

## 5. データ配置

```text
data/
  raw/<run-id>/active-users.csv
  raw/<run-id>/tokens.csv
  normalized/workspace-usage.jsonl
  state/import.json
```

- rawは追記専用とし、再調査と正規化処理の修正に利用する。
- normalizedは `date` を論理キーとして再取込時に置換する。
- stateには秘密情報を保存しない。
- アップロード上限は1ファイル5 MiBとする。

## 6. API

- `POST /api/import`: multipartで `active_users_file` と `tokens_file` を受け付ける。
- `GET /api/dashboard`: 保存済み集計と異常兆候を返す。
- `GET /health`: ヘルスチェックを返す。
- 入力不備はHTTP 400、ファイル上限超過はHTTP 413で返す。

## 7. セキュリティ

- `.env`、`data/`、実データCSVをGit管理しない。
- アップロード名を保存パスに使用せず、固定ファイル名で保存する。
- Dockerイメージに `.env` と利用データを含めない。
- MVPのWeb画面には認証を含めず、ローカルホスト向けとする。本番ではCognito等を必須とする。

## 8. 非機能要件

- 同じ日付の再取込で正規化レコードが重複しない。
- 取込失敗時に既存の正規化データを変更しない。
- 実データなしでfixtureを使ったテストを実行できる。
- Python 3.12、Docker Compose v2を対象とする。

## 9. 将来拡張

- 認証済みの取込APIをEventBridge SchedulerやECSタスクから呼び出す。

- 30日以上の履歴を使った曜日補正、季節性、変化点検知を追加する。
